대상: `F:\김도현박사님 자료\소스코드` (SOPHIA_gpu 인계본, 서울대 ESLAB; `.cuh` 29개 + `SOPHIA_gpu.cu`, 약 21,000줄; README, build/run 스크립트, `input/Leipzig_s10_dt01_full`, 50스텝 스모크 출력). 읽기 전용으로 분석했고(에이전트 5그룹 + 핵심 주장 6개 반박 검증), 모든 사실은 파일:행 근거가 워크플로우 기록에 있다(`subagents/workflows/wf_daacd315-ca4`).

## 1. 결론 요약
1. **유동 solver는 SPH다(ISPH, Eulerian SPH + EISPH).** 격자 볼츠만(LBM) 코드는 없다. 9/29에 전달받은 "LBM"은 오류이며 교수님 말씀이 맞다. 우리 저장소·문서의 "LBM" 표기는 모두 "SPH(ISPH-LES)"로 정정해야 한다.
2. **한 번의 유동 계산 = 35~42 시간(A100 80 GB)**, dt 0.01 s × 30,000스텝 = 300 s. 풍향은 +x로 고정이며 바꾸려면 입력 입자군을 다시 만들고(전처리 도구는 인계본에 없음) 전체를 다시 돌려야 한다. 풍속·멱지수(u_ref 10 m/s, 0.19)는 소스 하드코딩이라 수정 후 재컴파일이 필요하다. → **ROM(교수님 B안)은 풍향·풍속별로 각 2일의 GPU 계산과 전처리가 필요해 10/19까지는 불가능**하고, 현재 데이터(풍향 1개 1건)로는 기저를 만들 수 없다.
3. **시간 축 정정.** LDM은 10스텝마다(0.1 s) 움직이고 LDM 파일은 25스텝(0.25 s) 간격으로 600개(t = 150.25~300 s)다. 우리 환경은 파일 간격을 0.625 s로 가정했으므로(해석 A) T2 에피소드에서 플룸은 실제의 25 % 속도로 흘렀다. 방출률은 소스당 66.7 입자/0.1 s = **667 입자/s**(우리 가정 267). PF가 소스 강도를 주변화하므로 방법 간 순위는 바뀌지 않지만, 발표의 시간·Bq 표기는 정정해야 하고 최종 표 재계산 여부를 결정해야 한다(5절).
4. **우리가 "W2 = 상세 CFD 바람장"으로 쓴 것은 t = 300 s의 순간장 1개**(`fluid_30000stp.vtk`)다. 유동은 LES형 비정상 난류장이고(Deardorff SGS, 입자 고정 Eulerian SPH), 전체장은 t = 200·250·300 s 세 번만 저장된다. 150~299 s 시간 평균장(`mean_field.bin`, 861 MB)은 코드가 만들지만 인계본에는 없다(김도현 박사님 보유 여부 확인 필요). 즉 W2는 "참 바람장"이 아니라 "참 바람장의 한 순간"이며, 발표에 그렇게 적어야 한다.
5. **유동 재계산 없이 LDM만 다시 돌리는 모드가 있다**(`-DLDM_MEAN_MODE=1`, 시간 평균장 위에서). 소스 위치·개수·방출 일정은 LDM 텍스트 입력(입자당 한 줄)이라 재컴파일 없이 바꿀 수 있다. `mean_field.bin`만 있으면 새 소스·방출의 확산 데이터를 수십 분~2시간에 만들 수 있다(추정, 미측정). 단 평균장 위의 LDM은 분해 난류 없이 SGS 랜덤워크만으로 퍼지므로 비정상 LDM과 성격이 다르다.

## 2. 코드 사실 (연구에 쓰이는 것만)
### 2.1 유동
- 방법: 비압축성 Eulerian SPH, 예측자–수정자 투영법, PPE 1회 Jacobi 스윕(EISPH), KGC 구배 보정, Wendland C6 커널, h 3.75 m, κ 2 → 지지반경 7.5 m, 입자 간격 2.5 m, 4,304만 입자(유체 + 지면 4층 + 천장 3층 + 건물 IBM 마커 553,904). 입자 위치는 고정(격자와 같음).
- 난류: Deardorff 1방정식 SGS(DDF): ε = 0.93 k^1.5/l, ν_t = 0.1 l √k, k ∈ [1e-4, 5] m²/s²; `k_turb`·`e_turb` 출력은 **아격자(미분해) 난류**이고 분해 난류는 속도장 자체의 시간 변동에 들어 있다. 유입면에는 난류가 없다(정상 Dirichlet 멱법칙; 난류는 건물에서 생성).
- 유입: u(z) = 10·(z/371.25)^0.19 m/s, +x, u_y = 0(INIT_CROSSFLOW_UY = 0), 초기 조건도 같은 프로파일(충격 시작). 15 m에서 5.4 m/s, 10 m에서 5.0 m/s, 1.25 m에서 3.4 m/s. 유출: Orlanski 대류 조건. y: 정확 주기(주기 1297.5 m). 천장: 자유 미끄럼 + z ≥ 90 m Rayleigh 스펀지(u_z, u_y 감쇠). 지면: 무미끄럼 더미. 중립 성층(온도 300 K 고정, MOST 꺼짐). 속도 상한 20 m/s.
- 풍향 변경: 지원 안 됨(유입면 x = 0, 유출면 x = 1307.5~1317.5, 주기 y 고정). 90° 회전 = 입자 입력(건물 포함) 회전 재생성 + 완주.
- 비용: 4.2 s/스텝(A100), 체크포인트 10.9 GB/1000스텝, GPU 32 GB, 전체장 VTK 2.2 GB.

### 2.2 LDM(확산)
- 입력 `Leipzig_s10_dt01_full_LDM.txt`: 1,300,000행 = 13 소스 × 100,000 입자, 모두 z = 5 m, p_type 101~113, t_release 150.0~299.9985 s 균등(한 소스에 0.1 s마다 66.7개) → **667 입자/s/소스**.
- 이류: 유체 입자(p_type 1) 속도의 Shepard 정규화 SPH 보간(지지 7.5 m) + Ornstein–Uhlenbeck 랜덤워크(σ = √(2k/3), T_L = 2σ²/(C0 ε), C0 = 1.76; k, ε은 보간된 SGS 값). 전진 오일러 0.1 s.
- 경계: 지면 z = 0·천장 거울 반사, 건물 표면 1.25 m 이내 진입 시 반사; 유출 제거 없음(x ≈ 1315 넘으면 이웃이 없어 정지 → 우리가 본 x ≈ 1322 쌓임), y 주기 없음.
- 건식 침적(항상 켜짐): 지면 2 m 이내에서 Cs-137 1 µm 에어로졸 Wesely/Slinn 침적 속도로 확률 침적, 침적 입자는 z = 1e-4·속도 0으로 영구 고정(우리의 "지면 고정 입자" 규칙과 일치), 재부유 모델 포함.
- 출력 필드: `concentration` = 같은 소스 입자 중 7.5 m 이내 개수(자기 포함), `concn` = Σ(m/ρ)W(r)(격자 단위; m = 15.625 = 2.5³). 우리의 역공학 해석과 일치.

### 2.3 출력·시간
- 스텝 카운터 = solver 스텝(dt 0.01 s), 파일명 `<N>stp` = N스텝 수행 후 상태(t ≈ N × 0.01 s; float32 누적으로 150 s 게이트가 15001스텝에 열림).
- LDM 파일: 25스텝(0.25 s)마다, `LDM_15025stp` ~ `LDM_30000stp` 600개(solv의 plot-output frequency 50과 무관, 코드에 하드코딩). 우리 데이터와 정확히 일치.
- 전체장 `fluid_<N>stp.vtk`: 5000스텝마다, 게이트 이후 → 20000·25000·30000(t 200·250·300 s), 순간값(평균 아님). 슬라이스 `fluid_condition_*`: y ∈ [0, 7.5) m의 x–z 수직 슬랩(수평면 아님), 50스텝마다. 와도 500스텝마다.
- `mean_field.bin`: 150 ≤ t < 299 s의 모든 스텝 평균(u, v, w, k, ε), 299 s에 1회 저장(861 MB). 체크포인트 `restart.bin` 1000스텝마다.
- 데이터 위생 규칙(코드가 함의): x ≥ 1307.5(유출 완충대) 입자 제거, 침적 입자(z = 1e-4, 속도 0) 제거, 건물 내부 유체점(p_type 99 → buffer_type 99, 속도 0)은 VTK에 p_type 1로 섞여 있음 → 건물 마스크로 걸러야 함(우리 `dead_mask`가 이를 함).

## 4. 김도현 박사님께 확인·요청할 것
1. `out/mean_field.bin`(861 MB)과 생산 실행의 `run.log`가 남아 있는지.
2. 입자군·IBM 마커·LDM 소스 파일을 만든 전처리 스크립트(STL → 점군; x−30 m 오프셋의 출처).
3. 우리가 받은 `fluid_30000stp.vtk`가 생산 실행의 t = 300 s 순간장이 맞는지, 생산 빌드 플래그가 `build.sh`와 같은지(LDM_WALL_REFLECT_D, DD_WALL_DEP 기본값).
4. (가능하면) 평균장 위 LDM 전용 실행으로 소스 30~50개 데이터 생성, (여유가 있으면) 풍향 1개 추가(90° 회전) 완주.

## 5. 시간 축 정정의 선택지 (결정 필요)
- (a) **재표기만**: RL 1스텝 = 0.25 s, 드론 5 m/0.25 s = 20 m/s, 센서 적산 0.25 s(검출 효율 k0를 4배로 해석). 계산 불필요. 드론 20 m/s는 쿼드로터 상한권이라 설명이 필요하다.
- (b) **재계산**: RL 1스텝 = 1 s = LDM 파일 4개 진행, 드론 5 m/s·적산 1 s 유지. 150스텝 에피소드는 파일 600개가 필요하므로 100스텝(파일 400개, 시작 프레임 0~200) 또는 2대·W0/W1/W2 핵심 표만 재계산(기준 방법 3시간 + PPO 사슬 9개 약 20시간 + 평가 6시간 ≈ 1.5일).
- 권고: 10/9까지 (b)로 핵심 표(W0/W1/W2 × 기준 방법 + PPO 3시드, 2대)를 다시 만들고, 재현이 안 되면 (a)로 표기한다. 어느 쪽이든 결론의 논리(바람 수준 비교, 오라클 분리, 홀드아웃 일반화)는 바뀌지 않는다.
